# طراحی Agent Loop مبتنی بر LLM

تاریخ: ۲۰ اوت ۲۰۲۶

## مسئله

مسیر فعلی بعضی پیام‌های معتبر کاربر را پیش از فراخوانی مدل با regex طبقه‌بندی و با متن ثابت پاسخ می‌دهد. پیام‌های اجتماعی ترکیبی، سؤال‌های مبهم، retrieval کم‌اعتماد و خروجی کم‌اعتماد مدل ممکن است بدون دخالت LLM به پاسخ «شواهد ناکافی» یا متن تیکت تبدیل شوند. در نبود کلید مدل نیز برنامه بی‌صدا از DemoModelAdapter استفاده می‌کند و پاسخ نمایشی را شبیه پاسخ واقعی نشان می‌دهد.

## هدف

هر پیام معتبر و ماسک‌شده ابتدا توسط LLM فهمیده شود. مدل باید متناسب با Context یکی از دو کار را انتخاب کند:

1. پاسخ مستقیم و طبیعی به کاربر؛ برای گفت‌وگوی اجتماعی، سؤال تکمیلی، مرزبندی دامنه یا escalation.
2. فراخوانی ابزار `search_liara_docs`؛ برای پرسش‌هایی که به دانش مستندات لیارا نیاز دارند.

هیچ regex یا matcher محلی اجازه تولید پاسخ مکالمه‌ای یا تعیین نهایی Intent را ندارد.

## معماری

```text
ورودی API
  → اعتبارسنجی، محدودیت نرخ و ماسک اطلاعات حساس
  → LLM router با Context مکالمه و تصمیم ساختارمند search_liara_docs
      → respond_to_user: پاسخ مستقیم تولیدشده توسط مدل
      → search_liara_docs: اجرای RAG با query تولیدشده توسط مدل
          → LLM answer با اسناد بازیابی‌شده
          → اعتبارسنجی citation و حذف ادعای بدون ارجاع معتبر
  → SSE، متریک و workflow state
```

## قرارداد تصمیم مدل

تصمیم اولیه خروجی ساختارمند و اعتبارسنجی‌شده دارد:

- `action`: یکی از `respond` یا `search_docs`
- `intent`: Intent استنباط‌شده برای همان پیام
- `outcome`: یکی از `conversation`، `answer`، `clarification`، `escalation` یا `out_of_scope`
- `expertise_hint`: فقط برای تنظیم عمق پاسخ و غیرقابل‌نمایش به کاربر
- `response`: متن فارسی و طبیعی برای `respond`
- `search_query`: عبارت مستقل و بهینه برای RAG در `search_docs`
- `confidence`: اطمینان مدل به تصمیم

خروجی نامعتبر یک بار با repair prompt بازسازی می‌شود. شکست مجدد، خطای provider محسوب می‌شود و با پاسخ مکالمه‌ای ثابت پنهان نمی‌شود.

## سیاست پاسخ

- سلام، تشکر، خداحافظی و جمله‌های ترکیبی فارسی/انگلیسی را خود مدل پاسخ می‌دهد.
- سؤال فنی ناقص به یک سؤال تکمیلی متناسب با همان مسئله منجر می‌شود.
- سؤال فنی کامل ابزار جست‌وجوی مستندات را فعال می‌کند.
- نبود منبع مناسب به مدل گزارش می‌شود؛ مدل اجازه ادعای مربوط به لیارا بدون منبع ندارد، اما متن clarification را خودش تولید می‌کند.
- escalation فقط براساس درخواست صریح کاربر یا Context شکست تکرارشده توسط مدل انجام می‌شود.
- پاسخ خارج از حوزه کوتاه، محترمانه و متناسب با درخواست تولید می‌شود.
- زبان خروجی فارسی است؛ سطح تخصص هر پیام مستقل استنباط می‌شود و به کاربر نمایش داده نمی‌شود.

## منطق قطعی مجاز

متن ثابت فقط در لایه‌های غیرمکالمه‌ای مجاز است:

- خطای اعتبارسنجی HTTP و محدودیت نرخ
- ماسک Secret و جلوگیری از prompt injection
- خطای پیکربندی یا عدم دسترسی provider
- اعتبارسنجی schema و citation
- پیام retry در قطع شدن transport

این لایه‌ها نباید Intent، سؤال تکمیلی، متن تیکت یا پاسخ محتوایی تولید کنند.

## وضعیت Demo

نبود `GEMINI_API_KEY` نباید به‌طور خودکار DemoModelAdapter را فعال کند. Demo فقط با `DEMO_MODE=true` مجاز است و باید در متادیتا و UI قابل‌تشخیص باشد. در اجرای عادی بدون کلید، API خطای پیکربندی شفاف می‌دهد.

## Seam و آزمون‌ها

رفتار از seam عمومی `streamAgentTurn` و `POST /api/chat` آزموده می‌شود. adapter خارجی مدل می‌تواند fake شود، اما تابع‌های داخلی router mock نمی‌شوند.

سناریوهای الزامی:

1. `hi چطوری من خوبم` ابتدا به مدل می‌رسد، پاسخ طبیعی می‌گیرد و retriever اجرا نمی‌شود.
2. `سلام` پاسخ مدل می‌گیرد و متادیتا نام مدل واقعی را نشان می‌دهد.
3. `دامنه‌ام وصل نمی‌شود` یک clarification اختصاصی و تولیدشده توسط مدل می‌گیرد.
4. سؤال کامل دامنه ابزار RAG را فراخوانی و پاسخ citationدار تولید می‌کند.
5. retrieval بدون نتیجه همچنان به LLM برمی‌گردد و پاسخ ثابت ساخته نمی‌شود.
6. low confidence مدل با متن ثابت overwrite نمی‌شود.
7. درخواست صریح تیکت، متن متناسب با Context تولید می‌کند.
8. نبود کلید در حالت عادی به Demo سقوط نمی‌کند.
9. Secret پیش از هر فراخوانی مدل یا ابزار ماسک می‌شود.
10. citation نامعتبر هرگز به کاربر نمایش داده نمی‌شود.

## هزینه و کارایی

- پیام مستقیم: یک فراخوانی مدل و بدون retrieval.
- پیام مستند: یک تصمیم مدل، یک retrieval محلی و یک فراخوانی نهایی مدل.
- cache فقط برای پاسخ مستند عمومی و پس از اعتبارسنجی citation فعال می‌ماند.
- `deepseek-v4-flash` از طریق API سازگار با OpenAI در AvalAI برای router و answer استفاده می‌شود؛ adapter اجازه تفکیک مدل router و answer را در آینده بدون تغییر interface عمومی agent می‌دهد.

## معیار پذیرش

- هیچ مسیر موفق Chat بدون ثبت نام مدل واقعی در متادیتا پاسخ محتوایی تولید نمی‌کند، مگر Demo صریح.
- جست‌وجوی تمام رشته‌های فارسی در ماژول agent فقط prompt، status و خطاهای زیرساختی را نشان می‌دهد؛ پاسخ مکالمه‌ای ثابت وجود ندارد.
- تست واحد، Golden Set، تست زنده مدل در محیط دارای کلید، E2E دسکتاپ/تبلت/موبایل و production build پاس می‌شوند.
