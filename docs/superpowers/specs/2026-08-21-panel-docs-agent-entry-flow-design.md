# طراحی فلو ورود از پیشخوان و مستندات به دستیار لیارا

تاریخ: ۱۴۰۵/۰۵/۳۰ (2026-08-21)

## هدف

نسخه نمایشی باید نشان دهد کاربر از دو سطح آشنای لیارا—پیشخوان کاربری و مستندات—با کمترین اصطکاک وارد دستیار می‌شود. هر دو ورودی به یک فضای چت مشترک می‌رسند، اما حالت آغازین دستیار با مبدأ ورود تطبیق پیدا می‌کند.

این تغییر تجربه واقعی پنل یا مستندات را بازسازی کامل نمی‌کند. فقط بخش‌هایی پیاده می‌شوند که برای کشف دستیار، ورود به آن و برگشت به مبدأ لازم‌اند.

## منابع مرجع

- اسکرین‌شات پیشخوان خالی کاربر: `artifacts/liara-flow-audit/07-user-empty-dashboard.png`
- مخزن رسمی مستندات: <https://github.com/liara-cloud/docs>
- نسخه عمومی مستندات: <https://docs.liara.ir/>
- هویت بصری و لوگوی موجود پروژه: `public/brand/liara-logo.svg` و سبک‌های فعلی دستیار

مخزن مستندات با Next.js 14 و React 18 ساخته شده، اما برنامه فعلی از Next.js 16 و React 19 استفاده می‌کند. برای جلوگیری از دو runtime ناسازگار، سورس مستندات مستقیماً داخل برنامه import نمی‌شود. ساختار اطلاعات، متن‌های عمومی و زبان بصری آن به‌عنوان مرجع استفاده می‌شوند و صفحه نمایشی مستندات در همین برنامه ساخته می‌شود.

## محدوده

### داخل محدوده

- مسیر `/panel` برای شبیه‌سازی پیشخوان خالی و واردشده لیارا
- مسیر `/docs` برای شبیه‌سازی صفحه اصلی مستندات و ورودی دستیار
- مسیر `/assistant` برای ورود بدون فرم احراز هویت از صفحات نمایشی
- ورودی دائمی دستیار در نوار بالای پیشخوان
- ورودی ثانویه و زمینه‌مند در empty state پیشخوان
- ورودی «از دستیار بپرس» کنار جستجوی مستندات
- حالت آغازین متفاوت دستیار برای مبدأ پنل و مستندات
- نمایش مبدأ ورود و کنترل برگشت به همان مبدأ
- حفظ مسیر مستقل فعلی `/` و احراز هویت نمایشی آن
- واکنش‌گرایی و دسترسی‌پذیری پایه برای مسیرهای جدید

### خارج از محدوده

- بازسازی کامل پنل لیارا، منوهای حساب، مالی، اعلان‌ها و محصولات
- ساخت واقعی برنامه یا سرویس از دکمه «ایجاد برنامه»
- شبیه‌سازی پروژه، Deploy، Logs یا خطای سرویس
- واردکردن کامل سورس مخزن مستندات یا اجرای آن در runtime فعلی
- جستجوی واقعی در مستندات از صفحه نمایشی
- دسترسی خودکار دستیار به حساب، سرویس‌ها، اعتبار یا اطلاعات خصوصی کاربر
- ارسال خودکار سؤال یا محتوای سند به مدل
- ثبت واقعی تیکت

## معماری مسیرها

### `/`

مسیر فعلی دستیار مستقل و `MockAuthGate` بدون تغییر رفتاری باقی می‌ماند تا ورود و ثبت‌نام نمایشی موجود و تست‌های آن حفظ شوند.

### `/panel`

یک صفحه نمایشی client-light با پوسته‌ای وفادار به اسکرین‌شات فراهم می‌شود:

- نوار حساب، اعتبار نمایشی، اعلان، وضعیت و جستجو
- ناوبری «پشتیبانی»، «راهنما»، «مستندات»، «آموزش»، `CI/CD` و `API`
- ردیف محصولات لیارا
- empty state پلتفرم با تصویر یا asset واقعی موجود/مجاز، متن وضعیت و دکمه اصلی «ایجاد برنامه»
- لینک دائمی «دستیار» در نوار بالا
- لینک ثانویه «برای شروع از دستیار راهنمایی بگیر» زیر CTA اصلی

اطلاعات شخصی اسکرین‌شات مرجع کپی نمی‌شوند. نام، آواتار و اعتبار با داده نمایشی و غیرواقعی جایگزین می‌شوند.

هر دو ورودی دستیار به `/assistant?source=panel` می‌روند. دکمه «ایجاد برنامه» در نسخه اول نمایشی است و با متن کمکی روشن می‌کند که ساخت سرویس در این نمونه فعال نیست.

### `/docs`

صفحه نمایشی مستندات از معماری اطلاعات و زبان بصری مستندات رسمی پیروی می‌کند:

- سایدبار دسته‌های اصلی مانند پلتفرم، دیتابیس، هوش مصنوعی، Object Storage و ارجاعات
- هدر شامل لوگو، جستجوی نمایشی، ورود به پنل و CTA «از دستیار بپرس»
- محتوای صفحه اصلی شامل خوش‌آمدگویی، مسیرهای شروع سریع و چند کارت محصول
- لینک‌های محتوایی به صفحات واقعی `docs.liara.ir`

CTA دستیار به `/assistant?source=docs` می‌رود. جستجوی نمایشی قابل focus و تایپ است، اما نتیجه ساختگی نمایش نمی‌دهد و کاربر را برای جستجوی واقعی به مستندات رسمی هدایت می‌کند.

### `/assistant`

این مسیر از `ChatWorkspace` موجود استفاده می‌کند و با یک کاربر نمایشی ثابت وارد می‌شود؛ بنابراین کاربری که از پنل یا مستندات آمده دوباره فرم ورود نمی‌بیند. حساب نمایشی این مسیر هیچ داده شخصی واقعی ندارد و فضای ذخیره گفتگوهای آن با شناسه ثابت و نسخه‌دار از حساب‌های مستقل مسیر `/` جدا است.

پارامتر `source` فقط یکی از مقادیر `panel` یا `docs` را می‌پذیرد. مقدار نامعتبر یا مفقود به حالت عمومی دستیار تبدیل می‌شود. هیچ URL دلخواه یا متن آزاد دیگری از query string به مدل یا رابط تزریق نمی‌شود.

## قرارداد زمینه ورود

یک نوع کوچک و مستقل به نام `AssistantEntryContext` تعریف می‌شود:

```ts
type AssistantEntryContext =
  | { source: "panel"; returnHref: "/panel" }
  | { source: "docs"; returnHref: "/docs" }
  | { source: "direct"; returnHref: "/" };
```

یک تابع pure پارامترهای مسیر را به این قرارداد تبدیل می‌کند و جداگانه تست می‌شود. `ChatWorkspace` زمینه را دریافت می‌کند و فقط آن را برای UI آغازین و لینک برگشت استفاده می‌کند؛ زمینه بدون اقدام صریح کاربر به API چت ارسال نمی‌شود.

## تجربه آغاز دستیار

`EmptyState` از حالت ثابت به حالت قابل تنظیم ارتقا پیدا می‌کند.

### ورود از پیشخوان

- عنوان: «برای شروع روی لیارا چه کمکی می‌خواهی؟»
- توضیح: دستیار می‌تواند در انتخاب سرویس، آماده‌سازی پروژه و اولین استقرار کمک کند.
- پیشنهادها: انتخاب سرویس مناسب، آماده‌کردن پروژه Next.js، اتصال دامنه، مقایسه برنامه و سرور مجازی
- نشان مبدأ: «ورود از پیشخوان لیارا»
- لینک برگشت: «بازگشت به پیشخوان»

### ورود از مستندات

- عنوان: «در مستندات دنبال چه چیزی هستی؟»
- توضیح: کاربر می‌تواند سؤال خود را با زبان طبیعی بپرسد و پاسخ مستند دریافت کند.
- پیشنهادها: پیدا کردن صفحه مرتبط، توضیح ساده‌تر یک مفهوم، مراحل اولین استقرار، خطاهای رایج
- نشان مبدأ: «ورود از مستندات لیارا»
- لینک برگشت: «بازگشت به مستندات»

### ورود مستقیم

حالت و پیشنهادهای فعلی دستیار حفظ می‌شوند.

کلیک روی پیشنهاد فقط متن را مانند رفتار فعلی به چت ارسال می‌کند. ورود به صفحه به‌تنهایی هیچ پیام خودکاری ایجاد نمی‌کند.

## مرز کامپوننت‌ها

- `PanelDashboard`: فقط پوسته و رفتارهای ضروری پیشخوان نمایشی
- `DocsPreview`: فقط پوسته، navigation و CTAهای مستندات نمایشی
- `DemoAssistantGate`: ساخت کاربر نمایشی ثابت، خواندن زمینه ورودی و اتصال آن به `ChatWorkspace`
- `parseAssistantEntryContext`: تبدیل امن query string به قرارداد زمینه
- `EntryAwareEmptyState`: رندر متن و پیشنهادهای متناسب با زمینه؛ می‌تواند با توسعه `EmptyState` فعلی پیاده شود
- `ChatWorkspace`: مالک منطق گفتگو باقی می‌ماند و فقط props اختیاری زمینه و اقدام حساب/بازگشت دریافت می‌کند

صفحات نمایشی نباید منطق چت، storage یا authentication را دوباره پیاده کنند.

## رفتار ناوبری

- لوگوی پنل به `/panel` می‌رود.
- لینک «مستندات» پنل به `/docs` می‌رود.
- لینک «دستیار» و CTA empty state پنل به `/assistant?source=panel` می‌روند.
- لوگوی مستندات و لینک خانه به `/docs` می‌روند.
- «ورود به پنل کاربری» در مستندات به `/panel` می‌رود.
- CTA دستیار در مستندات به `/assistant?source=docs` می‌رود.
- کنترل بازگشت دستیار از قرارداد زمینه استفاده می‌کند و به مبدأ درست برمی‌گردد.
- سایر کنترل‌های غیرضروری یا به مقصد واقعی رسمی لینک می‌شوند یا با حالت غیرفعال و توضیح روشن نمایش داده می‌شوند؛ هیچ کنترل ظاهراً فعال نباید بی‌اثر باشد.

## طراحی بصری

### پیشخوان

- تم تاریک، RTL و تراکم نزدیک به اسکرین‌شات مرجع
- دو ردیف navigation با ارتفاع، border و فاصله‌گذاری مشابه مرجع
- accent فیروزه‌ای/سبز برند برای وضعیت فعال و CTAها
- حفظ سلسله‌مراتب: «ایجاد برنامه» CTA اصلی، ورود دستیار CTA ثانویه
- استفاده از آیکن‌های کتابخانه موجود و لوگوی واقعی محلی؛ عدم ساخت آیکن با متن یا CSS art

### مستندات

- تم روشن با سایدبار RTL و محتوای خوانا
- جستجو در هدر و CTA دستیار با تمایز کافی
- کارت‌های شروع سریع و محصولات با متن کوتاه
- لینک خروجی به مستندات واقعی برای جلوگیری از تولید محتوای ساختگی

### دستیار

- زبان بصری فعلی حفظ می‌شود.
- نشان مبدأ و لینک برگشت باید کوچک، قابل فهم و مزاحم جریان گفتگو نباشند.
- CTAهای پیشنهادی compact باقی می‌مانند، اما target حداقل 44 پیکسل و focus واضح دارند.

## دسترسی‌پذیری و واکنش‌گرایی

- همه مسیرها RTL و دارای landmarkهای `header`, `nav`, `main` و نام‌های دسترس‌پذیر هستند.
- ترتیب keyboard مطابق ترتیب دیداری است و focus در ورود صفحه قابل پیش‌بینی باقی می‌ماند.
- لینک‌ها و دکمه‌ها از نظر semantic جدا هستند؛ navigation با `Link` و action با `button` پیاده می‌شود.
- CTAهای ثانویه با CTA اصلی اشتباه نمی‌شوند و contrast حداقل AA هدف‌گذاری می‌شود.
- در موبایل، ردیف محصولات به scroll افقی کنترل‌شده تبدیل می‌شود و محتوای اصلی بدون zoom افقی قابل استفاده می‌ماند.
- سایدبار مستندات در موبایل به drawer تبدیل می‌شود.
- رفتار واقعی keyboard، focus، reflow و screen reader در تست و مرور مرورگر بررسی می‌شود؛ از روی اسکرین‌شات ادعای انطباق کامل WCAG نمی‌شود.

## حالت‌های خطا و محدودیت

- query نامعتبر دستیار به حالت مستقیم و امن بازمی‌گردد.
- نبود JavaScript نباید لینک‌های اصلی میان صفحات را از کار بیندازد.
- دکمه‌های نمایشی ساخت سرویس و جستجوی محلی پاسخ ساختگی تولید نمی‌کنند.
- اگر API چت در دسترس نباشد، رفتار خطای فعلی `ChatWorkspace` حفظ می‌شود.
- اگر storage مرورگر در دسترس نباشد، خطای موجود گفتگو نمایش داده می‌شود؛ صفحات پنل و مستندات همچنان قابل مشاهده‌اند.

## تست

### واحد

- تبدیل `source=panel`, `source=docs` و مقدار نامعتبر به `AssistantEntryContext`
- انتخاب متن، پیشنهادها و مقصد برگشت برای هر مبدأ
- اطمینان از اینکه metadata مبدأ ورود هرگز به payload چت اضافه نمی‌شود؛ فقط متن پیشنهادی‌ای که کاربر صریحاً انتخاب یا ارسال کرده وارد payload می‌شود

### کامپوننت

- حفظ CTA اصلی «ایجاد برنامه» و حضور CTA ثانویه دستیار در پیشخوان
- حضور ورودی دستیار و لینک پنل در مستندات
- متن و نشان مبدأ صحیح در empty state دستیار
- نمایش کنترل بازگشت صحیح بدون تغییر رفتار گفتگوی مستقیم

### E2E

- `/panel` پیشخوان خالی را نشان می‌دهد و CTA دستیار به حالت پنل می‌رود.
- لینک «مستندات» پنل مسیر `/docs` را باز می‌کند.
- `/docs` CTA دستیار را نشان می‌دهد و ورود به حالت مستندات انجام می‌شود.
- `/assistant?source=panel` بدون نمایش فرم ورود، heading پنل و بازگشت به `/panel` را نشان می‌دهد.
- `/assistant?source=docs` بدون ارسال خودکار پیام، heading مستندات و بازگشت به `/docs` را نشان می‌دهد.
- مسیر `/` همچنان رفتار ورود، ثبت‌نام و چت مستقل فعلی را حفظ می‌کند.
- مسیرهای جدید در viewport دسکتاپ و موبایل بدون overflow مخرب قابل استفاده‌اند.

## معیار پذیرش

- کاربر از هر دو صفحه نمایشی با یک اقدام روشن وارد همان دستیار می‌شود.
- هیچ فرم ورود اضافه در مسیر پنل یا مستندات نمایش داده نمی‌شود.
- حالت آغاز دستیار مبدأ ورود را درست منعکس می‌کند و هیچ پیام خودکاری نمی‌فرستد.
- پیشخوان از نظر پوسته، دو ردیف navigation، empty state و رنگ‌بندی به مرجع کاربر وفادار است.
- مستندات از نظر sidebar، header، جستجو و کارت‌های شروع به ساختار رسمی وفادار است.
- داده شخصی اسکرین‌شات در کد یا UI نهایی کپی نمی‌شود.
- واردکردن سورس Next.js 14 مستندات باعث تغییر runtime برنامه Next.js 16 نمی‌شود.
- lint، typecheck، تست‌های واحد و E2E هدفمند عبور می‌کنند.

## ملاحظه مجوز

مخزن مستندات عمومی است و README اجرای محلی و مشارکت را توضیح می‌دهد، اما در بررسی فعلی فایل مجوز صریحی در ریشه مخزن پیدا نشد. این پیاده‌سازی برای نمونه محلی از ساختار و زبان بصری به‌عنوان مرجع استفاده می‌کند و کپی کامل سورس را وارد پروژه نمی‌کند. هرگونه بازتوزیع عمومی نسخه تغییریافته مستندات باید پس از تأیید مجوز از لیارا انجام شود.
